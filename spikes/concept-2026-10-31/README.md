# コンセプト確認スパイク（2026-10-31）

> **使い捨て。** 実データ 2 社分（Cloudflare・Vercel）で簡易シナリオを回し、モデルとスキーマの穴を探すためのもの。
> 本体の設計（10 進数・スキーマ・出所の型）には従っていない。料金は 2026-10-31 に公式ページから取得した値（[data.ts](./data.ts) に出典）。

```bash
node --experimental-strip-types run.ts      # 要約
node --experimental-strip-types run.ts -v   # 明細つき
```

## シナリオ

Next.js（App Router）製の記事 + コメントのサイト。記事ページは ISR（60%）、個人化されたページは SSR（40%）、
1 PV あたり API 1 回・アセット 10 個・画像 5 枚。画像は 5,000 種類 × サイズ違い 3。仮定はすべて `run.ts` の `A` にまとめてある。

| 構成 | 内容 |
|---|---|
| Cloudflare + vinext | Workers + D1 + R2。ISR のキャッシュは KV、画像の最適化は Images |
| Vercel + Supabase | Next.js をネイティブで。DB は Supabase（Micro） |
| さくらの VPS | 2GB（東京）に nginx・`next start`・MySQL を同居。**1 プランに固定**（ユーザーの指示・2026-10-31。上位プランは後から足す） |

## 結果（USD/月。円建ては 1 USD = 150 円の仮定で換算）

| 月間 PV | CF Free | CF Paid + vinext | Vercel Hobby + Supabase Free | Vercel Pro + Supabase Pro | さくらの VPS 2GB |
|---|---|---|---|---|---|
| 1 万 | ✗ | **10.15** | ✗ | 45.00 | 13.05 |
| 10 万 | ✗ | **10.15** | ✗ | 45.00 | 13.05 |
| 100 万 | ✗ | **10.15** | ✗ | 45.00 | 13.05 |
| 1000 万 | ✗ | 33.68 | ✗ | 899.38 | **13.05**（回線 85%） |

- **最安の構成が 100 万〜1000 万 PV の間で入れ替わる**（Cloudflare → VPS）。企画書 §4.4 の体験の核が、実データで再現した。
- VPS は上限にかからない限り固定費だけで、効いてくるのは CPU（9%）ではなく**共有回線**（85%）。
- Vercel Pro + Supabase Pro は 100 万 PV まで基本料の $45 から動かない（クレジットで相殺）。1000 万 PV では転送量（FDT $651）が支配的。
- `-v` で、各構成の明細と「前提」（● 当たっている / ◐ 境目の半分を超えた / ○ まだ遠い / ・ 常に効く事実）が出る。

## 見つかった穴・困難（重要な順）

### 1. 量ではなく「アプリの形」で成立・不成立が決まる

Cloudflare Free は 1 万 PV でも成り立たない。原因は量ではなく、**SSR 1 回の CPU 時間（仮定 15 ms）が上限 10 ms を超える**こと。
仮定を 8 ms にすると結論が反転する。**いちばん効くのは料金ではなく、測っていないアプリの性能の仮定**。
→ こうした仮定は**不確かさの幅にせず、選択肢として表に出す**（ユーザーの方針・2026-10-31）。
見積では「重要な前提」として、どの値を境に成立・不成立や最安構成が入れ替わるかを添える。
ゲームでは「アプリケーション最適化」のような行動の選択肢になる（企画書 §5.4）。PRD 01 §8「判断ポイント」。

### 2. 公式の文書の中で食い違いがある

Vercel Pro の込み分は、pricing ページ（1000 万リクエスト・1 TB 込み）と Pro の文書（クレジットは最初の 1 単位から、Flat Rate CDN）で書き方が違う。
100 万 PV で $20 と $107 の差（5 倍）になる。Function Invocations も、表では N/A、本文では $0.60/1M と書かれている。
→ 幅にすると見積としてもゲームとしても成り立たない（ユーザーの判断・2026-10-31）。**最もらしい解釈に固定**し、
退けた解釈は根拠つきで記録だけ残す。固定した解釈は、実際の Pro プランの使用量と請求で確かめる（[calibration-vercel-pro.md](./calibration-vercel-pro.md)）。

### 3. 「未取得」の明細が合計を過小にする

> 2 回目で KV・Images・Supabase・さくらの VPS を取得し、未取得は解消した。所見そのものは有効。

vinext の ISR は KV、画像の最適化は Cloudflare Images に依存する。**フレームワークを載せると、別の製品が芋づる式に入ってくる。**
今回は KV と Images の料金を取っていないので、Cloudflare の合計は下限でしかない。
→ 「料金未取得」を第一級の状態にする。合計は「下限（未取得 N 件）」と表示し、0 円として黙って足さない。
データ収集の範囲は「サービス」ではなく、**DeployTarget が要求する製品の閉包**で決まる。

### 4. ホストの実装によってリクエストクラスが変わる

同じ ISR でも、Vercel では CDN が返す（関数は再生成のときだけ動く）。vinext + KV では**閲覧のたびに Worker が動き、KV を読む**。
→ DeployTarget はメーターの対応だけでなく、**クラスの経路を変える**写像を持つ必要がある（06 §2.3 を強める）。

### 5. 件数が PV ではなくコンテンツの量で決まるメーターがある

画像の変換は「画像の種類 × バリアント数」、ISR の再生成は「ページ数 × 期間 / 間隔」で頭打ちになる。
1 万 PV でも Hobby の画像変換の上限（5,000）を超えたのは、画像 5,000 枚 × 3 バリアントを置いたため。
→ Workload に**コンテンツの在庫**（ページ数・画像数・更新頻度）を、トラフィックとは別の軸として足す。

### 6. 支配的な費用は転送量で、転送量の仮定が最も効く

規模が大きくなると、FDT（Vercel）と egress 無料（Cloudflare・R2）の差が総額をほぼ決める。
画像サイズとブラウザキャッシュの再利用率が少し動くだけで、桁が変わる。→ 画像の圧縮・サイズ違いの数・キャッシュ設定を判断ポイントにする（1 と同じ扱い）。

### 7. 規約上の制約は数量の上限ではない

Vercel Hobby は商用利用が不可。量が上限内でも使えない。→ スキーマに**利用資格（eligibility）**を足す。
シナリオ側に「商用か」を持たせて判定する。

### 8. 地域で単価が変わる

Vercel の Active CPU・メモリは地域ごとの表（0.128〜0.221/h）。CDN・FDT・ISR・画像も地域料金（表は未取得）。
→ 関数の地域は構成の入力、**閲覧者の地域分布**は Workload の入力として要る。

### 9. 導出できない量がある（Fluid の同時処理）

Vercel の Provisioned Memory は「インスタンスの生存時間」で課金される。1 インスタンスが同時に何件さばくかに依存し、
リクエスト単位の数値からは決まらない。今回は同時処理 1（上限側）で置いた。→ 幅を持った仮定として扱う。

### 10. 上限を超えたときの挙動は、プランの性質だけでなく利用者の設定でもある

Vercel Pro は既定では上限なし。予算を設定すると一時停止にできるが、数分の遅れがある。Hobby は超過で「30 日待つ」。
Cloudflare Free は UTC 0 時までエラーを返す。→ OverageBehavior の一部は**構成の設定**にする。停止の長さは可用性の評価に効く。

### 11. 料金データの変化が速い

取得した各ページの最終更新は 1〜3 か月以内だった。**施行日つきの予告**（D1 の結果サイズ上限が 2026-11-04、
Workers Logs の課金変更が 2026-12-01）や、**メーター名の変更**（Edge Requests → CDN Requests）もある。
→ PriceBook に将来の施行日を持つ改定を入れられるようにし、メーターに別名を持たせる。

### 12. 丸めが書かれていないことがある

Workers の CPU ms の丸めは記載なし。R2 は「次の課金単位へ切り上げ」（1.1 GB 月 → 2 GB 月）。
→ `rounding` に「記載なし」を表せるようにする（仮定で埋めたことが分かるように）。

### 13. 小さい規模では差が固定費に吸収され、比較がつまらない

100 万 PV まで Cloudflare Paid は $5.15、Vercel Pro は（解釈 A なら）$20 のまま動かない。
→ 小さい規模では金額よりも「次に費用が増える段差まで、あとどれだけ余裕があるか」と「成立・不成立」を見せるほうが情報が多い。
ゲームでは、この段差を超える瞬間がイベントになる。

### 14. 前提には「量の境目」と「常に効く事実」の 2 種類がある

「1 日 10 万リクエストまで」は量の境目で、近さ（%）を出せる。「2GB プランは SLA 非対応」「最低利用期間 3 か月」は量がなく、
月額には効かないが、**ゲームの可用性・移行の費用**に効く。→ 前提を 2 種類に分ける（量の境目は判定と距離、事実は説明と、ゲーム側の効果）。

### 15. コンテンツの在庫で決まる費用が、小さい規模の順位を決める

Cloudflare Paid が 1 万 PV から $10.15 なのは、Images の一意な変換（5,000 種類 × 3 = 15,000 件）が込み分の 5,000 を超えるため。
PV にかかわらず $5 が乗り、VPS（$13.05）との差が縮む。所見 5 が、実際に順位へ効いた例。

### 16. フレームワークの実装の細部が、最大の不確かさになる

Cloudflare 側の 1000 万 PV で最大の明細は KV の書き込み（$17.35）。これは「vinext は内容が変わらなくても再生成のたびに KV に書く」という**未確認の仮定**による。
Vercel は「内容が変わらなければ ISR の write は 0」と明記している。→ フレームワーク × ホストの振る舞いも、料金と同じく**出典つきで確かめるデータ**（06 の DeployTarget）。

### 17. ISR の効き目はページあたりの閲覧密度で決まる

再生成の回数を「閲覧 / (1 + λT)」（λ: ページあたりの閲覧の頻度、T: 再検証の間隔）で見積もると、2,000 ページ・300 秒の設定では
**閲覧の 74〜100% が再生成になる**（1000 万 PV で 74%、1 万 PV でほぼ 100%）（1 ページあたりの閲覧が間隔より疎いため）。人気がページに偏れば（Zipf）大きく変わる。
→ 「ISR を使えば安い」は前提しだい。人気の偏りは判断ポイントの候補。

### 18. 税込と税抜が混ざる

さくらの VPS は税込の円、Cloudflare・Vercel・Supabase は税抜のドル（Supabase は売上税の導入を予告）。そのまま並べると比較が歪む。
→ PriceBook に「税込か」を持たせ、見積の方針（税抜で揃える / 税込で揃える）を決める。為替は仮定（今回は 1 USD = 150 円・未取得）。

### 19. 月額と支払いの時期が一致しない

さくらの VPS は初回に 2 か月分の前払い・最低利用期間 3 か月。Supabase の Compute は 1 時間単位で切り上げ、支出上限の対象外。
→ 長期運用を前提にするので、当面は**調べた範囲を備考として残すだけ**にする（ユーザーの判断・2026-10-31。D-14）。システムに反映するかは保留。

### 20. 回線のような「共有で保証のない上限」は仮定で置くしかない

さくらの VPS は 100 Mbps の共有回線で、実際に使える帯域は書かれていない（今回は 50% を仮定）。メモリの常駐量（MySQL・Node）も仮定。
→ VPS の判定は、ほぼすべてが判断ポイント（所見 1 と同じ扱い）。上位プランを足すとき（4GB は SLA 対応）は、この仮定がそのまま乗り換えの判断になる。

## Vercel Pro の解釈

**採用: pricing ページの込み分（CDN Requests 月 1000 万・Fast Data Transfer 月 1 TB）が残り、$20 のクレジットはそれ以外の従量と超過分に当たる。**

- pricing ページは、資源ごとの込み分を明示した料金表になっている（「10M / month included; then starting at $2 per 1M」）。
- Pro の文書の「from the first unit you use」は、込み分のない資源（Active CPU など）に最初の 1 単位からクレジットが当たる、と読めば両立する。
- Pro の文書の Flat Rate CDN は「For content delivery, you can pay on demand or through Flat Rate CDN」とあり、選べる別の方式と読める。

退けた解釈: 込み分がなく、すべての従量に最初の 1 単位からクレジットが当たる（100 万 PV で $107。採用した解釈では $20）。
→ 実請求で確かめる（[calibration-vercel-pro.md](./calibration-vercel-pro.md)）。CDN Requests が 1000 万未満の月に、その明細が $0 なら採用した解釈が正しい。
