# 16. 画面の情報の絞り方と図の使い方（UI の指針）

> 状態: **指針（2026-11-15）**。始める画面の整理（D-214〜D-221）で、ユーザーと 1 つずつ確かめながら決めた匙加減をまとめたもの。ゲーム中の画面にも当てはめた（D-222）。見積モードに広げるときの基準にする。
> 個々の決定の経緯は決定ログ（D-214〜D-222）が正典。ここは「次の画面でどう判断するか」を書く。画面に当てはめる段取りは §7（スキルにする場合も、中身はこの文書を読む）。

## 1. 目的

- 画面を開いた人が、**何を選べるか・今どうなっているか・どこに問題があるか**を、文を読まずに掴めるようにする。
- 説明は消さずに**畳む**。読みたい人は 1〜2 回押せば読める。
- 実装は**daisyUI の部品で済む形**を優先し、自前の JS・位置の計算を増やさない。

## 2. 見せる層（3 段）

| 層 | 置き場 | 入れるもの |
|---|---|---|
| ① 常に見せる | カード・欄の本体 | 選ぶもの（タブ・チップ・ボタン）、今の選択、**問題**（黄・赤の札・注意）、図（構成図・見取り図・手間のマス）、図に添える数 1 つ（「機能開発に毎月 8 pt」） |
| ② 1 回押すと見える | カード右上の ⓘ のダイアログ | 短い説明（1〜2 文）、図の読み方（凡例。見出しと見本つき） |
| ③ もう 1 回押すと見える | ⓘ の中の「詳しい説明を見る」（開閉。chevron つき） | 長い文、前提（SLA・席・仮定）、用語、描き方ごとの説明（折りたたみ） |

- **ⓘ はカードの右上に 1 つ**。チップ・札・行ごとに ⓘ を並べない（例外は §4）。
- 層を決めかねたら、下の層（畳む側）に置いて、ユーザーに見てもらってから上げる。

## 3. 振り分けの問い

上から順に当てはめ、最初に「はい」になった層に置く。

1. **それが無いと選べない・操作できないか** → ①（タブ・チップ・プランのボタン）
2. **問題を示しているか**（制限に当たる・選べない・規約違反） → ①（札・注意。ただし満たしているものは出さない → §4）
3. **図で言えるか** → 図を ① に置き、文は ② か ③ へ（手間の内訳はマスの色、流れは線の色）
4. **別の場所と重なっていないか**（遊び方・ダイアログ・別のカード） → 重なるなら消す（「12 か月を走り切りましょう」・乗り換えの注記は遊び方に任せた）
5. **図の読み方か** → ②（凡例）
6. **それ以外の説明** → ③

迷ったときの目安:

- **選んで結果が変わらないものは、選ばせない**（コメント欄の描き方。どの組でも同じか悪くなるだけなら、既定にして選択肢ごと外す。D-220）。
- **数は 1 つに絞り、残りは図か ⓘ に**（手間は「機能開発に毎月 N pt」だけ。D-218）。
- **用語は利用者の言葉で**（「鮮度」→「反映スピード」。D-220。「既定から変わっている: 選んだ描き方（…の既定は…）」→「既定（ISR）から変更」。D-219）。

## 4. 残す側に寄せる例外

削りすぎると不安になる・迷うものは、① に残す。

- **単位**: 数には単位を付ける（pt・$・回）。単位が無いと何の数か分からない（D-218）。
- **見出し**: 凡例・札の並びには何の一覧かの見出しを付ける（「構成図の矢印の色」「注意が必要な制限:」。D-218・D-220）。
- **色の対応**: 説明の中で札・線に触れるときは、本体と同じ色・同じ形で出す（「それぞれの説明」の頭はカードと同じ色の札。凡例の線の先には矢印）。
- **選べないことと理由**: 選べないものは灰色で残す（隠さない）。理由は**まとめて 1 つの ⓘ**（「選べない選択肢について」）に出し、チップごとに ⓘ を並べない（D-220）。
- **問題のある判定だけ出す**: 満たしている判定（✓）は ① に出さず、△・✗ だけを出す（D-219）。

## 5. 型の一覧（実装済みのもの）

| 型 | 使いどころ | 実装 |
|---|---|---|
| カード右上の ⓘ 1 つ | カードの説明を全部まとめる | `info.tsx` の `Info`（ダイアログ） |
| 「詳しい説明を見る」 | ⓘ の中の長文 | `info.tsx` の `MoreDetails`（開閉・chevron） |
| 問題だけの札 + 「それぞれの説明」 | 要件の判定 | `route-plan-table.tsx` の `RowStatus`（`issuesOnly`） |
| 「選べない選択肢について」 | 選べない描き方・設定 | `route-plan-table.tsx` の `UnavailableInfo` |
| 図 + 数 1 つ | 手間の内訳 | `scenario-briefing.tsx` の `EffortBar`（マス）と `EffortDetail`（ⓘ の中の凡例） |
| 凡例は ⓘ の中 | 図の色の意味 | `system-diagram.tsx` の `LaneLegend`（見出し・矢印つき） |
| 説明ごとの折りたたみ | 選択肢が多い説明 | `route-plan-table.tsx` の `StrategyExplain`（daisyUI の collapse） |
| 入れ子のタブ | 欄の切り替えと選択肢 | 外: `SetupTabs`（`tabs-box`。タブと中身を 1 つの面で包む）・内: `choice-tabs.tsx`（`tabs-lift`。選んでいるもののカード 1 枚） |
| 狭い画面のタブ | 選択肢が横に入らない | ロゴだけ・均等の幅（`flex-1`。選んでも幅が変わらない）。名前は読み上げとカードの見出し |
| 選択肢の枠 | 説明の文と並ぶ選択肢 | 枠（`ring-1`）。選んでいるものは太い枠と塗り（`PartOptions`・プランの `join` のボタン） |
| 中身の多いものはダイアログ | 部品の差し替え・説明 | 構成図の箱も ⓘ と同じダイアログ（吹き出しにしない。D-221） |
| 良い・悪いの対比 | 効果の説明 | 色と矢印のパネル（`TrendingUp` / `TrendingDown`。D-216） |
| 図の読み方は図の見出しの ⓘ | 輪のグラフ（内側・外側・目盛り） | `feature-ring.tsx`（見出しと色の凡例だけ残す。D-222） |
| 重なる内訳は図に任せる | 手間の横棒と全区分の表 | 輪のグラフの凡例（0 の区分は出さない）に任せて外した（D-222） |
| 見込みと目安を 1 行に | 所持金の見込み・目標の目安 | `trends.tsx`（出し方と目安の意味は ⓘ。D-222） |
| 別の欄と重なる推移は畳む | 上限の使用率の推移 | daisyUI の collapse。先で超える見込み（▲）があるときだけ開く（D-222） |
| グラフの注記はカードの ⓘ | 除いた月・区切った月・上端で切った値 | `TrendCard`（D-222） |
| 欄の説明・選んだ値の説明は欄の ⓘ | アクションの設定 | `actions.tsx`（手間・来月からの 1 行と「今は効かない」・警告は本体に残す。D-222） |

## 6. 試して戻したもの（匙加減の境目）

| 試したこと | 戻した理由 |
|---|---|
| 良い・悪い効果に顔のアイコン | 色と矢印で十分に分かる（D-216） |
| 「伸びる」「減る」の見出し | 何が伸びるのか分からない（D-216） |
| ⓘ の中の手間をマスなしの文だけ | 図が無いと直感的でない。ⓘ にも図と凡例（D-218） |
| 「詳しく比べる」の表 | 使い方が分かりにくい割に情報が多い。ソースだけ残す（D-220） |
| 狭い画面だけ箱を吹き出し→ダイアログ | 実装が面倒になる。どの幅でもダイアログに統一（D-221） |
| タブを折り返す | 複数列で見づらい。ロゴだけで 1 行に（D-221） |
| 「右に続きがある」印（自前の JS） | daisyUI で済む形を優先（D-221） |
| 選んでいるタブを事業者のブランド色に | タブと中身の境目が不自然（D-221） |
| カルーセル（両脇のカード・スワイプ） | 仕組みが複雑。タブ + 1 枚のカードで足りる（D-221） |

## 7. 進め方

- **1 つの指摘ごとに直して、remote dev で見てもらう**。まとめて直すと、どれが効いたか分からない。
- 削る前に、**消すのか・畳むのか・別の場所に任せるのか**を決める（§3 の 4）。
- 方針を変えたら決定ログに書き、覆した側に「一部改定済み」の印を付ける。
- テストは「出ないこと」も確かめる（畳んだものが本体に出ない・ⓘ を開くと出る）。
