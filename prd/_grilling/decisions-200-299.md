### D-200 分布の読み込み中は「▼ あなた」を出さず、最初の読み込みは同じ高さのスケルトンにする（D-175・D-197 の見直し。2026-11-10・ユーザーの指摘）

- 依頼（ユーザー。supervisor 経由）: 統計を読み込むとき「▼ あなた」の位置がジャンプするのが良くない。
- 原因:
  - 統計の画面（D-197）: シナリオ・絞り込みを切り替えると、読み込み中は前の分布を薄く残すが、自分の値は**新しい**シナリオの最新の完走から取っていた。前の分布の範囲（ビンの両端）の上に新しい値を置き、届いた分布の範囲で描き直すので印が跳んだ。最初の読み込みでは分布の欄も比較の図も無く、届いた時点で全部が現れた（下が押し下がる）。
  - 比較の図（`GroupCompare`。両方の画面）: 軸を切り替えると、前の軸の区切り（`binEdges`）のまま新しい軸の値で自分の線を引き（`groupRangeLayout` は自分の値で横の範囲を広げる）、届くと描き直して跳んだ。最初は「読み込んでいます。」の 1 行で、届くと図の高さに伸びた。
  - 結果の画面: 絞り込みの切り替え中は前の分布の範囲の上に自分の値（同じ値）を置き、届いた分布の範囲で印が動いた。全部の分布の読み込み中は分布の欄が無く（手元の履歴の比較を出し）、届くと入れ替わった。比較の図は全部の分布が届くまで出さなかった。
- 決定（推奨案）:
  - **最初の読み込み**（まだ 1 度も取れていない）は、ヒストグラムの欄と比較の図に同じ高さのスケルトンを出す（`charts.tsx` の `HistogramSkeleton`・`GroupChartSkeleton`。動きなし・`region-skeleton.tsx` と同じく静的な淡い塊）。この間、「あなた」の線と印・統計の画面の「あなた $x」は出さない。比較の図のスケルトンは、行の数が届くまで分からないので並び（隠した構成を除いた構成・フレームワーク）の数で見込む（集計が溜まって全部の行が揃ったときの高さ。それまでは届くと縮むことがある）。
  - 結果の画面は、全部の分布の読み込み中に 4 軸の分布の欄（同じシード・全シードの 2 本）をスケルトンにし、比較の図もスケルトンで出して取りに行かない（`GroupCompare` の `defer`）。統計の画面も最初は 4 軸のカードと比較の図をスケルトンで出す。
  - **切り替え中**（前の表示を薄く残している間）は、前の分布の棒は残し、「あなた」の線と印は新しい分布が届くまで出さない（`HistogramChart`・`GroupHistogramChart` の `hideMine`。印の段の高さは取っておく）。結果の画面の絞り込み・統計の画面のシナリオと絞り込み・比較の図の軸と分け方のどれにも効く。
- 実装: web の `charts.tsx`（`hideMine`・`HistogramSkeleton`・`GroupChartSkeleton`）・`result-axes.tsx`（`ResultAxesPanel` の `hideMine` とスケルトン）・`stats-breakdown.tsx`（`GroupCompare` の `defer`・`hideMine`・最初のスケルトン、`ResultStatsSection`）・`stats-mode.tsx`（`AxisCard` のスケルトンと `hideMine`）。テスト: `stats-breakdown.smoke.test.tsx`（W-109b・W-109c）・`stats-mode.smoke.test.tsx`（W-117）。
- 残した点: 結果の画面で全部の分布が 10 件未満・取れないと分かったときは、スケルトンが手元の履歴の比較（段 1）に替わるので高さが変わる。見た目（スケルトンの高さが実際と揃うか）は実機で確かめる。
- 正典: [prd/15](../15-results-and-stats.md) §7 の段 3。

### D-201 今の構成では受けられない提案は、返事を待たない知らせにして断ったことにする（2026-11-11・ユーザーの決定）

- 依頼（ユーザー。supervisor 経由・試験プレイの指摘）: 今の事業者では受けられない提案（SLA の打診など）も返事待ちになり、閉じただけで「次の月へ」を押すと未決の確認（D-140）が毎回出る。
- 決定（1C）:
  - 起きる月の構成で `unavailableReason` が理由を返す提案（要件を満たせるプランが今の事業者に無い。今のデータでは `p-sla`・`c-p-sla` をサーバーレスの構成で受けたとき）は、返事待ち（`pendingProposals`）に入れず、`phase: 'occurred'` の知らせにする。本文は提案の文に「今の構成では受けられません: 理由」を続けたもの。理由は `MonthEvent.unavailable` にも入れ、画面は「返事は不要・受けられないので、断ったことになります」を添える。受ける / 断るの欄は出さない。
  - `responses` には起きた月に 'declined' と記録する（今までは翌月の初めに `declineUnanswered` が記録していた。断ったときの効果は無いので結果は変わらない）。
  - 乱数・時期は変えない: 台本はそのままで、起きる月の構成で中身だけ替える（D-118 の `preempted` と同じ扱い。`month/traffic.ts` の `Due.unavailable`）。
  - 予告（「法人から SLA つきの契約の打診が来そう」など）は、予告を出す月の構成で受けられないなら「ただし今の事業者では『稼働率の SLA があるプラン』を選べないので、来ても受けられない見込みです」を添える（プラン変更で受けられる VPS 2GB には添えない）。
- golden（`game.test.ts`）・基準プレイ・組み合わせの総当たりは変わらない。
- 実装: game の `month/traffic.ts`（`scriptOf`）・`month/play.ts`・`month/notices.ts`・`state.ts`（`MonthEvent.unavailable`。`accept.unavailable` は前の版の保存の報告にだけ残る）。web の `EventCard`。テスト: game の `unavailable-proposal.test.ts`（サーバーレスの `p-sla`・`c-p-sla` は返事待ちに入らず declined・VPS 2GB は今までどおり）・`components.test.ts` の SLA の打診。web の `proposal-dialog.smoke.test.tsx`（W-201）。

### D-202 出来事のダイアログの提案のページで、受ける / 断るを選べるようにする（D-140 の見直し。2026-11-11・ユーザーの決定）

- 依頼（ユーザー。supervisor 経由・試験プレイの指摘）: 出来事のダイアログで提案が出るが、受ける操作は行動の欄の奥にあり道筋が見えにくい。
- 決定（1A）:
  - 出来事のダイアログ（`EventsDialog`）の提案のページに、行動の欄と同じ受ける / 断るの欄を出す。行動の欄の提案の行を部品 `ProposalChoice`（web の `proposal-choice.tsx`）に切り出し、両方で使う。ダイアログでは見出し（題・説明）を出来事の通知に任せ、「受けるか断るかを選びます（選ばなければ断ります）」と来月の手間の残り（行動の欄の見出しと同じ「来月の手間の残り n / m」）を添える。受けられないときは、行動の欄と同じ理由（手間が足りないなど）を出す。
  - 返事の状態（`answers`）と行動の組み立て（`build`）など、今月の行動の下書きを `Actions` から `Game` に持ち上げた（web の `month-draft.ts` の `useMonthDraft`）。ダイアログで選べば行動の欄にも付き、行動の欄で選び直せばダイアログにも付く。判定・説明は 1 か所（`checkActions`・`acceptSummary`）。
  - ダイアログで返事を選んであれば、「次の月へ」の未決の確認（D-140）は出ない（確認そのものは残す。選ばずに閉じた提案があれば今までどおり出る）。
  - 出来事の通知の「受けると: …」の文は、すぐ下で選べるダイアログでは「月の終わりの行動で受けるか断るかを選びます」を省く。ダイアログの中の radio は矢印キーで選び直すので、矢印でのページ送りは radio の上では効かせない。
- D-140 の「提案ごとに受ける・断るをダイアログの中で選ぶ形は採らない（判定・説明が二重になるため）」を見直した。下書きを共有して判定・説明を 1 つの部品にまとめたので、二重にならない。
- テスト: web の `proposal-dialog.smoke.test.tsx`（W-202a ダイアログで選んだ返事が行動の欄に付き、行動の欄で替えるとダイアログにも付き、確認なしで進む・W-202b 受けられない理由をダイアログにも出す）。`App.smoke.test.tsx` の W-61 を新しい文言に合わせた。W-85〜W-87（確認の流れ）はそのまま通る。

### D-203 提案を受けると止まりうる上限を、今 → 受けると の使用量で先に出す（2026-11-11・ユーザーの決定）

- 依頼（ユーザー。supervisor 経由・試験プレイの指摘）: 受けると容量が増える提案が、止まる上限（Cloudflare D1 の 10 GB・VPS のディスク 100 GB など）を越えても事前に分からない。
- 決定（2B）:
  - 提案の効果に関わる止まりうる上限（提案の `premiseRefs` に当たる量の境目のうち、効き方が止まる・プランの変更が要るもの。メールの送信だけのものは除く）について、提案のカード（ダイアログ）と行動の欄の提案の行に「今 0.4 GB → 受けると 9.4 / 10 GB（残り 0.6 GB）」のように、今 → 受けると の使用量と上限を常に出す。受けても使用量が変わらない上限（伸び方だけが変わる・保存量の効果が無い提案）は出さない。
  - 受けると来月止まるなら、赤（文字は `text-error-strong`・「✗ 止まる」の印）で「受けると来月止まります」と、引き上げられるか（同じ事業者のプラン変更・ストレージ変更オプションで止まらなくなるか）を添える: 「（プランの変更などで上限を引き上げれば止まりません）」/「（この上限はプランの変更では引き上げられません）」。
  - 来月は止まらなくても、今の規模のまま残りの月のうちに届く見込みなら、黄（「● 止まる見込み」の印）で「今の規模なら n か月後に止まる見込みです」（来月 = 1 か月後）。ためていく量（保存量）だけ。
  - 受ける操作は止めず、確認のダイアログも足さない。色だけに頼らず印と文で言う。数字は「今月選んでいる行動を当てた、今の規模（基準の PV）での見込みです。PV が伸びれば早まります」と断る。
- 計算（game の `accept-preview.ts`。表示のためだけで、ゲームの状態には入れない）:
  - `acceptPreview(state, eventId, actions?)`: 今月選んでいる行動（この提案への返事は除く）を当てた base と、そこに「受ける」の効果（`applyEffects`）を当てた after に、それぞれ来月の料金表で `monthEstimate`（基準の PV。出来事・乱数は含めない）を引き、前提を `{ id, text, unit, effect, limit, before, after, stops, raisable?, monthsUntil? }` で返す。今月の行動で同じ事業者の別のプランにする（Cloudflare Paid → Free など）と前提の id のプランが替わるので、制限・枠の前提はプランを伏せて `premiseRefs` と比べる（`refMatches`。supervisor の確認で、Free を登録すると表示が消えていたのを直した）。DB などの差し替えの最中は、playMonth と同じく移行先の部品も動かしている構成で見積もる（`monthEstimate` の `withSwap`。OCL-F585BA69）。`stops` の規則は `month/outcome.ts` の `stopsSite`（`premiseOutcomesOf` の止まる判定と共用）。
  - `monthsUntilLimit(state)`: playMonth と同じ在庫の伸び（`stockOf`）を基準の PV で 1 か月当てた見積との差を 1 か月の増分とし、まっすぐ伸ばして上限を越える月を出す。最後の月までに届かなければ出さない。推移の外挿（`premiseTrends`）とは別。
  - 見込みは、出来事の無い月に実際に受けて進めた翌月の使用率・当たり・止まったかと一致する（テストで突き合わせた）。
- テスト: game の `accept-preview.test.ts`（記事の引き取り × Cloudflare D1 で止まる・引き上げられない・越えなければ見込みの月・VPS でストレージ変更オプション / 4GB を選ぶと越えない・保存量の効果の無い提案と課金だけの前提は空・入力を変えない・決定論・翌月との突き合わせ）。web の `proposal-dialog.smoke.test.tsx`（W-203a 赤・W-203b 黄・W-203c「構成を変える」で Cloudflare Free を登録すると赤）。
- 残した点: 伸び方だけを変える提案（監査ログの DB の増え方 × 3・添付の 3 倍など）は、来月の使用量が変わらないので出していない（受けた後の推移の見込みで分かる）。PV の伸びを含めた見込みにはしていない（今の規模で断る）。赤・黄の見え方と、狭い画面での折り返しを実機で確かめる。

### D-204 完走のダイアログの高さを dvh で抑え、分布は「全シード / 同じシード」を 4 軸まとめて切り替えて 1 本だけ出す（D-161・D-200 の見直し。2026-11-11・ユーザーの指摘）

- 依頼（ユーザー。supervisor 経由）: iPhone で完走のダイアログが縦に収まらず、下の「閉じて結果を見る」が見えない。中身は 4 軸それぞれに同じシード・全シードのヒストグラムが 2 本ずつ積まれている。
- 原因: daisyUI の `modal-box` の既定の `max-height: 100vh`。iOS Safari の 100vh はツールバーを畳んだときの高さなので、ツールバーが出ている間は箱が画面より高く、上下にはみ出していた（見出しとボタンを固定し中身だけスクロールする形（OCL-3AA8C258）は、箱の高さが画面に収まって初めて効く）。
- 決定:
  - 完走のダイアログの `modal-box` に `max-h-[calc(100dvh-2rem)]`（出来事のダイアログと同じ考え方）。見出しとボタンは固定、4 軸の欄だけスクロール。
  - 4 軸の欄（`ResultAxesPanel`。完走のダイアログと結果の画面で同じ部品）の上に、見る分布の切り替えのチップ「全シード（n 件）」「同じシード（n 件）」を 1 つ置き（`chips.tsx` の `Chips`。aria-pressed）、4 軸すべてのヒストグラムを選んだ方の 1 本だけ出す。既定は全シード（件数が多い方）。選んだ方は `infra-supra:dist-scope` に覚え、同じ画面に出ているもう片方の欄もそろえる。
  - 選んでいない方の要約（「同じシード 12 件中 上位 x%」など）の 1 行は残さない（推奨案）。件数はチップに添える。上位 % は見ている方の要約に出る。
  - 「★ 上位」の印・花火・見出しの「n つの軸で上位」は切り替えによらず今のまま（`rankBasisOf`・`MIN_RANKED_COUNT`）。切り替えは見るためだけと注記に書いた。
  - 最初の読み込みのスケルトンは 1 本分の高さにした。読み込み中に「あなた」を隠す扱い（D-200）はそのまま。
- 実装: web の `result-axes.tsx`（`useDistScope`・`DIST_SCOPE_KEY`）・`chips.tsx`（`stats-breakdown.tsx` から移した）・`game-screen.tsx`（完走のダイアログ）。テスト: `stats-histogram.smoke.test.tsx` の W-204（既定が全シード・件数つきのチップ・4 軸がそろって替わる・結果の画面もそろう・覚える・上位の判定と花火は変わらない・ダイアログの高さ）と、W-98・W-100b・W-101・`stats-breakdown.smoke.test.tsx` の W-104・W-105・W-109b を 1 本の形に合わせた。
- 残した点: iPhone の実機で、ダイアログの下のボタンが見えることを確かめる。

### D-206 幅 360px でヘッダーがはみ出さないよう、右端のボタンを狭い画面で 32px の正方形にする（2026-11-11・supervisor の指摘）

> 見直し → D-210（狭い画面では「戻る…」と「新しいゲーム」を 1 つのメニューにまとめた）

- 依頼（supervisor）: 幅 360px のゲームモードで、ヘッダーが 5px はみ出してページが横にスクロールする。左の「ゲーム / 見積 / 統計」のタブ（統計のタブ。D-197）と右端のボタン群（戻る…・新しいゲーム・遊び方・設定。`shrink-0`）で 365px。
- 原因: 右端のボタンは sm 未満で既に文字を隠してアイコンだけだったが、左右の余白（`px-2`・遊び方は daisyUI の `btn-sm` の既定の余白）が残り、アイコン 16px に対してボタンが 34〜42px あった。
- 決定（表示だけ）: sm 未満では「戻る…」「新しいゲーム」「遊び方」を設定と同じ 32px の正方形（`w-8 px-0`。sm 以上は今までどおり文字つき）にし、ボタンの間（`gap-0.5`）も詰めた（sm 以上は `gap-1` のまま）。見込みで 20px ほど縮み、360px でも収まる。名前は今までどおり aria-label（「過去の月に戻る…」「新しいゲーム」「遊び方」「設定」）と title。タップの的は高さ 32px（`btn-sm`）のまま（44px に広げると幅が足りなくなるため、今の大きさを保った）。タブの余白（daisyUI の `--tab-p`）は CSS の層の優先が読みにくいので触らなかった。見積・統計のモードは右端が設定だけなので、ゲームモードより狭い。
- 実装: web の `App.tsx`。テスト: `narrow-screen.smoke.test.tsx` の W-206（統計のタブまで出した形で、ボタンの名前と順・狭い画面の正方形のクラス・文字は sm 以上だけ・見積と統計は設定だけ）。jsdom では幅を測れないので、`documentElement.scrollWidth <= 360` は supervisor がブラウザで確かめる。

### D-207 4 軸の欄の上の説明を 1 行にし、数え方の詳しい説明は ⓘ に畳む（D-161・D-204 の見直し。2026-11-11・supervisor の指摘）

- 依頼（supervisor）: 完走のダイアログの 4 軸の欄（`ResultAxesPanel`）の上の説明（集計した分布と比べていること・上位 25% の数え方・④ は上位を数えない・切り替えは見るためだけ・自分を数えたか）が 390×664 の画面で 6 行ほどあり、最初に見える軸が 1 つだけになる。
- 決定（表示だけ。上位の判定・花火は変えない）:
  - 分布と比べるとき（集計が ready）の注記は 1 行「集計した完走のプレイの分布と比べています。」（結果の画面の絞り込み中は「{絞り込みの名前}の完走の分布と比べています。」）。開発用の架空の分布は頭に「開発用の架空の分布です。」だけ残す。

### D-213 構成図の foreignObject の中に独自のレイヤーを作る要素を置かない（iPhone の Safari で箱と線・枠がずれる。2026-11-11・ユーザーの指摘）

- 症状: iPhone の Safari で、始める画面の縦の図の箱だけが左上に寄り、事業者の枠（点線の角丸）と矢印は正しい位置にあるので箱と線がずれる（Google Cloud の構成で大きい）。WebKit（Playwright の webkit・390px）では Cloudflare の構成でも下の段の箱が矢印の先とずれ、枠の下半分が空いた。Chromium では出ない。ラベルと右上の「!」が重なるのは Chromium でも出た。
- 原因（推定）: WebKit は foreignObject の中で独自のレイヤーを持つ要素（position: relative / absolute・opacity・transform・filter・overflow など）を、SVG の viewBox の拡大縮小と foreignObject の位置を受けずに描く。縦の図の箱はボタン（`relative`）の中の HTML で枠と地を描き、印は `absolute`、幽霊の箱は `opacity`、読み上げの補足は `sr-only`（absolute）だった。縦の図は `maxWidth: 幅 × 1.5` で拡大して中央に寄せるので、ずれが大きく出る。
- 決定（規則）: **構成図の foreignObject の中に、位置指定（relative / absolute / fixed / sticky。`sr-only` も）・opacity・transform・filter・overflow（`line-clamp` も）など独自のレイヤーを作る class・style を置かない。** SVG の要素（rect など）の opacity は foreignObject の外なので構わない。
  - 縦の図の箱（`CompactNode`）: 地と枠を SVG の rect で描く（地はボタンの下、枠は上に重ねて `pointer-events: none`。枠の太さは前の CSS の border と同じく箱の内側に収める。幽霊の箱は点線 `4 3`・地の `fillOpacity` 0.5）。ボタンは同じ太さの透明の枠を持ち、ホバーの地・inset の輪・フォーカスの輪は今までどおりボタンに付ける。短い名前の `line-clamp-3` はやめ、はみ出しは foreignObject の切り抜きに任せる。
  - 右上の印（⇄・「!」）: 縦の図・横の図の差し替えられる箱（`SwappableNode`）とも、foreignObject の外に SVG の円と字で描く（`BoxMark`。`data-swap-mark`・`data-unselected-mark` はその g に付く。押しても下のボタンに届くよう `pointer-events: none`）。縦の図の印は箱の右上の角に重ねる（半径 6・外へ 4 はみ出す。名前との重なりは下の補足）。印の影（`shadow-sm`）と「!」の title（ホバーの「未選択」）は落とした（読み上げの名前に「未選択」がある）。
  - 幽霊の箱・見出しの薄さ: opacity をやめ、字の色の透明度（`text-base-content/70`・幽霊の箱は名前 /50・見出し /35）にした。事業者の枠の見出しの `opacity-80` も `text-base-content/80`（ロゴは薄くしない）。
  - 読み上げの名前: `sr-only` が置けないので、info.tsx の `Popover` に `hiddenName` を足し、ボタンの中の `hidden` の要素（吹き出しの名前と同じ文字列）を `aria-labelledby` で指す。aria-label は付けず、名前は見えている文字で始まる（D-196 の WCAG 2.5.3 は保つ）。一番下の段の箱は SVG の外なので `nameFromContent` + `sr-only` のまま。Popover の吹き出しは `getBoundingClientRect` から `position: fixed` で置くので、ボタンの `relative` には頼っていない（Popover の既定は変えていない）。
- 補足（同日・supervisor の WebKit での確認）: 上の形で箱と矢印・枠のずれは直った（Google Cloud・Cloudflare）。ただ、印の分の `pr-3` で幅が狭くなり「Firebas / e Hosting」のように英単語の途中で折れ、`line-clamp-3` をやめたので「R2 公開バケットのキャッシュ」が箱の上下にはみ出して切れた。
  - 決定: **縦の図の箱の短い名前の行はモデルで決める**（`system-diagram-model.ts` の `compactText`）。ブラウザに折り返しを任せず、各行を `whitespace-nowrap` の行として描く。選んだ理由: 折り返しの CSS（`break-words` か `keep-all`）では「英単語は切らない・和文は字ごとに切る」を両立できず（`keep-all` は空白の無い和文を 1 行にする）、省略の `-webkit-line-clamp` は `overflow: hidden` を伴い WebKit の foreignObject の中でレイヤーになる。モデルで決めれば、どの構成の名前も収まるかをテストで総当たりにできる。縦の図用の短い名前を構成ごとに手で持つ案は、部品が増えるたびに書き足す必要があるので採らなかった。
